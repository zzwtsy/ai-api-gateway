# 信息架构

## 1. 一级导航

```text
监控
├── 概览
├── 请求
└── 分析

配置
├── 连接
├── 模型
├── 路由
└── 客户端

系统
└── 设置
```

导航顺序反映实际使用频率与任务关系，不按数据库实体排序。

## 2. 页面合同

| 页面 | 用户要回答的问题 | 主操作 | 主结构 |
| --- | --- | --- | --- |
| 概览 | 系统是否正常，哪里需要处理 | 切换时间范围、进入问题 | 开放式 KPI、主趋势、待处理事项、紧凑表格 |
| 请求 | 一次逻辑请求发生了什么 | 筛选、发送测试请求、导出 | Master–Detail 排障工作台 |
| 分析 | 谁在消耗、哪里不稳定、成本如何 | 过滤、切换指标、导出 | 指标切换、趋势图、拆分表、错误构成 |
| 连接 | 厂商 Endpoint 与账号是否可用 | 添加连接、添加账号、测试 | Provider 目录 + 耐久详情 |
| 模型 | 哪些上游模型可用，能力和价格来自哪里 | 同步、添加绑定 | 高密度表格 + Persistent Inspector |
| 路由 | 请求将匹配哪条规则并去向哪里 | 创建、模拟、发布 | 规则表 + 解释预览；独立编辑器 |
| 客户端 | 每个 Harness 使用什么 Key 和路由范围 | 添加客户端、轮换 Key | 高密度表格 + Persistent Inspector |
| 设置 | 系统如何保存数据和运行 | 分区保存 | 左侧本地导航 + 开放式设置行 |

## 3. 全局顶栏

全局顶栏只承担跨页面能力：

- 面包屑；
- 演示数据或环境标识；
- 全局搜索；
- 快速创建；
- 系统状态。

禁止把当前页面的主要操作长期放在全局顶栏。比如“创建路由”“添加连接”“导出请求”必须回到页面标题区。

## 4. 全局搜索

`Ctrl/Cmd + K` 打开 Command Dialog。搜索至少覆盖：

- 页面；
- Request ID；
- 客户端；
- 请求模型与实际上游模型；
- 路由名称；
- Provider。

结果按对象分组。每个结果必须显示对象类型、主名称和足以区分的辅助信息。选择结果后直接进入对应页面并定位对象，而不是只打开页面顶部。

## 5. 快速创建

快速创建只保留最高频的跨页创建动作：

- 连接厂商；
- 创建路由；
- 添加客户端。

模型绑定通常依赖已存在的连接，因此不作为默认快速创建项；用户从连接或模型页进入更符合上下文。

## 6. URL 与可恢复状态

以下状态应进入 URL，便于刷新、返回和分享：

- 当前页面；
- 请求筛选、分页、选中 Request ID、Inspector Tab；
- 分析时间范围和维度筛选；
- 连接选中的 Provider 与详情 Tab；
- 模型筛选和分页；
- 路由列表筛选；
- 设置分区。

已交付对象详情使用 `requestId`、`connectionId`、`modelBindingId` 与 `clientId`。Route Search Schema 拥有参数名、默认值省略和无效值规范化；跨页入口使用 `routes/-deep-links.ts` 中面向真实消费者的 Builder，不在 Feature 中复制 Search 对象。

以下状态不进入 URL：

- 未提交表单中的 Secret；
- 一次性完整 Key；
- Toast；
- 临时确认框；
- 未保存的敏感字段。

## 7. 跨页关系

页面之间必须形成可解释的跳转：

```text
概览问题 → 请求详情 / 连接账号 / 模型详情 / 分析
请求详情 → 账号健康 / 路由策略 / 添加备用目标
连接 → 模型绑定 / 账号 / Endpoint / 兼容性
模型 → 来源与覆盖 / 使用该模型的路由
路由 → 匹配模拟 / 相关请求
客户端 → 生成配置 / 发送测试请求 / 该客户端请求
```

跳转必须携带上下文。例如从请求详情点击“查看账号健康”，连接页应直接打开对应 Provider 的账号 Tab。
