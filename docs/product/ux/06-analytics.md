# 分析页

## 1. 页面目标

分析页用于比较不同 Harness、客户端、Provider、账号、模型和协议的使用量、稳定性、性能和成本。它不用于单次请求排障。

## 2. 筛选区

筛选项：

- 时间范围；
- 客户端；
- Provider；
- 模型；
- 协议。

筛选修改后通过“应用”提交，避免每次选择都触发昂贵聚合。当前筛选写入 URL，并在导出时保持一致。

## 3. 指标切换

顶部四个开放式 Metric Switch：

- 逻辑请求；
- 估算费用；
- 最终请求错误率；
- P95 TTFT。

选中状态使用边框、背景和排版，不依赖彩色大卡片。切换指标只改变主图和相关口径说明。

## 4. 主图

当前周期与上一周期对比。支持按小时和按天聚合。

口径：

- Request 数不包含重试；
- 费用按 Attempt 的实际上游模型与历史价格快照计算；
- Request 错误率与 Attempt 错误率分开；
- TTFT 只对收到首字节的请求统计，并明确样本数。

## 5. 下方分析

### 5.1 按客户端拆分

列：请求数、占比、最终错误率、P95 TTFT、费用。点击进入客户端详情或带筛选的请求页。

### 5.2 错误构成

按稳定错误分类展示数量和占比：429、连接超时、401/403、流中断、其他。错误分类必须来自规范化错误码，而不是直接使用供应商原始文案。

### 5.3 可选扩展

后续可增加 Provider、账号、模型和协议拆分，但沿用同一表格与筛选模式，不新增大面积仪表盘卡片。

## 6. unknown 与费用

任何费用合计必须同时说明：

- 已知价格覆盖的请求或 Attempt 数；
- unknown 数量；
- 是否包含包月内、免费额度或厂商报告费用；
- 价格来源和快照时间。

unknown 不进入已知费用总和，也不按 0 计算。
